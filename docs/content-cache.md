# 原件缓存与流量

客户端使用两套用途明确的缓存，均由程序维护，不属于cap正文或员工草稿。Git缓存服务同步、精确版本运行和Skill注册，其锁、完整性及发布规则继续维护于[缓存架构](architecture.md#同步与运行)；本说明维护CLI get、Office预览和工作台原件读取的轻量缓存及查询流量。

## 原件复用

小原件缓存按服务端根地址、cap名称和原生entry隔离，只保存该入口最近使用的一份字节。服务端以实际Git blob的强ETag标识原件；仅修改简介或详述时，未变原件仍有相同ETag，无需重新下载整个Office或媒体文件。

缓存字节位于CAPSULE_CLIENT_HOME/content-cache/files，登记、ETag、字节数、摘要和LRU位于顶层client.sqlite的content_cache表。文件以0600模式原子发布，拒绝符号链接和越界登记；Windows 的读取权限继承本机私有目录的 NTFS ACL，不以0600模式代替ACL。读取验证文件长度、摘要以及字节与Git blob ETag的绑定。缓存不保存员工授权、Bearer或租约凭证，也不在cap内部增加登记。

每次使用仍向服务端发送带当前身份的条件GET，只有服务端确认同一ETag的304才使用已验证的本机字节。没有权限时返回真实401/403/404，不离线回退旧内容；同名cap重建也须重新鉴权。cap提交号和token从本次响应取得，Office继续保留读取前后版本核对，旧原件不能冒充当前版本。

默认单文件最多16MiB，已登记原件缓存最多128MiB、256条，按LRU回收；发布临时文件需要额外空间，这也不是进程总内存上限。小文件以有界Buffer交给消费者，回收其他缓存不会破坏正在返回的内容。同一entry跨进程串行，重复请求只做条件重验；索引及容量回收使用独立短锁。只清理这套可重新取得的派生缓存，不触及Git缓存、本机改动、Skill state或恢复原件。

中断在文件发布与索引提交之间留下的未登记缓存，也在索引锁内按严格生成文件名核对并回收，避免绕过容量统计。未知名称和符号链接保留并报错，不按目录大小或文件年龄盲目清理。

工作台对超过上限或未知长度的原件直接流式传输，不为缓存预读整个文件。Range、HEAD和浏览器条件请求直接交给服务端，不因请求少量视频字节而下载全片；原件读取不下载整个cap的Git历史。Office结构化预览仍受16MiB解析上限及ZIP/XML限制。

浏览器原件读取各自拥有取消信号：中断请求或未完成的响应关闭时，停止自己的缓存锁等待、上游传输和未发布缓存；正常GET请求接收完毕产生的close不当作断连。相同entry的其他读者不共享该信号，仍按原锁顺序继续；已完整发布、校验合法的缓存保留，供后续重新鉴权后使用，不因某个浏览器未消费而删除。索引锁等待中的取消同样清理本次claim，不把取消前收集的字节迟到发布。

旧服务端未提供可用强ETag时保留原读取能力，不把无法重验的响应放入持久缓存。原件缓存缺失或已损坏时重新取得派生字节；未知文件和不安全路径明确拒绝，不自动清空整个客户端工作区。Git缓存出现脏内容或完整性错误仍按原策略停止，不套用原件缓存的回收规则。

## HTTP与下载

服务端内容GET/HEAD返回强ETag、X-Capsule-Commit和X-Capsule-Token。If-None-Match命中时304不带正文；If-Match不符返回412，If-Range仅在验证一致时保留分段传输。每种情况先鉴权，再判断是否省略正文。浏览器收到private, no-cache，复用前仍须重新验证；Office恢复原件、整库备份和管理响应继续no-store。

嵌入Markdown媒体可携正文的version token，经本机桥接在上游响应头阶段核对X-Capsule-Token；GET、Range、HEAD和304错版均409/CONTENT_VERSION_CHANGED并取消正文，避免旧正文配新附件。此检查在预读或缓存发布之前，拒绝不删除已有合法缓存；用户明确下载当前原件不附旧正文version。原件本身仍使用现有ETag重验，version不是新的认证凭据或cap字段。

普通原件与Office恢复原件采用30分钟读取期限，并在浏览器断连时结束自己的流式下载；恢复原件不沿用普通JSON请求的30秒期限。这是只读取消，不会自动取消、撤销或重放已经提交的上传与保存。

ApiClient仅在明确的条件读取中允许304，其他重定向仍拒绝。CLI下载在发起请求前检查本地目标，已有文件不产生远端传输；最终发布仍用不覆盖的hardlink，防止检查后出现新文件。流式下载失败不留下伪完整目标，也不自动重放写操作。

## 查询调度

隐藏标签暂停内容、属性、身份、只读活动和普通事件列表查询，恢复可见立即刷新。编辑租约续期及未完成Office保存的回执核对继续运行，不能为了省流量丢失占用或把未知结果显示为成功。

属性先查询轻量版本与当前权限，版本未变不重取详述。Office只读会话每30秒检查，编辑空闲每10秒；保存中采用快速确认，不再叠加工作区的重复会话轮询。跟踪事件只查对应eventId，整页列表另按可见状态刷新。

浏览器仅合并白名单中的进行中只读请求，返回各自独立对象；通用请求层不保留跨轮询TTL缓存；分段阅读器另维护有界、展示前重验权限和版本的段落缓存，约束见[阅读界面](ui.md)。写入、上传、心跳、租约续期、独立AbortSignal和携租约的请求不合并；写操作开始及结束会隔离旧的进行中读取，避免写后取得写前结果。授权和保存结果始终以服务端为准。

## 验证范围

隔离真实HTTP测试统计原件响应字节，覆盖重复读取、仅改说明、真实内容变化、条件GET、HEAD、Range、撤权、断连取消及错版媒体拒绝；缓存测试覆盖跨进程、损坏、配额及路径边界。Playwright在隔离Chromium中以可控计时器和请求计数验证慢读、切换取消、最近分段复用、撤权和延迟配图恢复，具体用例见[前端测试说明](ui-testing.md)。公司网络压测与Windows原生文件系统行为需要在对应环境单独验证。
